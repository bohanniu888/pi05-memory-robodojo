# 结果与证据

以下数字均归档自 2026-10-18/19 的本地运行，并不代表 RoboDojo 官方榜单协议。官方 native 50-trial 评测尚未
完成。

## 评测协议

- 任务：`cover_blocks`、`match_and_pick_from_conveyor`、`swap_T`、`press_by_number`、
  `imitate_sorting_sequence`、`swap_blocks`。
- seeds：0、1、2。
- 每个任务/seed 的集数：6（共尝试 108 集；其中 90 集有效，因为 `swap_blocks` 在推理前失败）。
- 策略 server 与 Isaac client 使用不同 GPU。
- score 为每集 return 的均值 × 100；成功率单独报告。

## 内容敏感性门禁

`on` 使用正确历史；`zero` 清空历史内容；`croll` 提供滚动后/错误的历史。定义：

```text
Δ = loss_bad_history − loss_on
```

如果模型使用了记忆内容，错误历史应使损失升高。因此修正后的通过判据是
`Δ ≥ +1e-4` 且 `t > +5`，而不是负阈值。

| 检查点（checkpoint） | Δ(zero−on) | t | Δ(croll−on) | t | on 损失 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5,000 | +2.37e-2 | +55.0 | +1.01e-3 | +7.1 | 0.002228 |
| 10,000 | +1.68e-1 | +58.5 | +7.07e-3 | +7.1 | 0.002185 |
| 15,000 | +9.28e-2 | +42.2 | +3.76e-3 | +6.6 | 0.001899 |
| 19,999 | +1.47e-1 | +38.2 | +6.02e-3 | +6.0 | 0.001724 |
| Phase 8 kf 19,999 | +2.9e-6 | +0.3 | +3.1e-6 | +0.4 | 0.001579 |

v2 内容通路明显处于激活状态，但任务层面的提升很小。对历史内容敏感并不等同于具备有用的回忆能力。

## `swap_blocks` 失败

client 在 Isaac/PhysX 场景 reset 路径中以 `PhysX Internal CUDA error 700` 崩溃；策略 server 记录的推理调用数为
零，因此与模型无关。针对性的十环境对照如下：

| 变体 | 结果 |
| --- | --- |
| 原始场景，重复 1 次 | `PHYSX700` |
| 原始场景，重复 2 次 | `PHYSX700` |
| `cover_blocks` 对照 | 通过，502 s |
| 立方体材质变体 | `PHYSX700` |
| 小垫子变体，重复 1/2 次 | `PHYSX700` / `PHYSX700` |
| `skip_reloc`，重复 1 次 | 通过，482 s |
| `skip_reloc`，重复 2 次 | `PHYSX700` |
| `no_app_update` | `PHYSX700` |
| 带详细诊断的正常场景 | `PHYSX700` |

结论：跳过 articulation relocation 不是稳定修复。触发点会在不同 scene-reset 操作之间漂移，根因仍未闭环。
在归档的 6 任务分数中应将此任务记为失败，但不要把失败归因于模型权重。
